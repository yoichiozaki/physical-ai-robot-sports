# DECISIONS.md — 設計判断の記録

形式: 判断 / 代替案 / 理由。新しい判断は末尾に追記する。

## D-001 開発環境: Docker ベースの Dev Container（python:3.11-slim-bookworm）
- 代替案: `mcr.microsoft.com/devcontainers/python`（大きい）、Conda、ホスト Python。
- 理由: 要件「ホストに Python を入れない」「再現性」。slim イメージ + 必要な apt パッケージのみで軽量化。ワークスペースは bind mount のため再ビルド後も成果物が残る。

## D-002 PyTorch は CPU 版をコンテナに固定、GPU は任意
- 代替案: CUDA 版 torch（GTX 1650 4GB）。
- 理由: SB3 の MlpPolicy + PPO は CPU の方が高速（小さなネットワーク・環境律速）。イメージも小さい。Colab ではプリインストールの CUDA 版 torch を使う。

## D-003 ロボット機構: 2 軸直交ガントリー（X: ブリッジ, Y: キャリッジ）
- 代替案: 2 リンク平面アーム（SCARA）。
- 理由: 実在のエアホッケーロボットの主流構成で、XY 平面 2 自由度という要件に一致。各軸 slide joint + 速度サーボアクチュエータ（力制限付き）で、位置・速度・加速度制限を物理的に表現できる。ブリッジは重く（X 軸の加速度が小さい）、軸ごとに異なる制約を持つ。

## D-004 パックはスライド関節 (x, y) で平面拘束、衝突形状は球
- 代替案: free joint の円柱がテーブルに接触する方式。
- 理由: エアホッケーはエアクッションで浮上しており、垂直運動とテーブル接触は本質ではない。平面拘束 + 球形状にすると、マレット・壁との衝突法線が厳密に水平となり、MuJoCo の凸衝突（MPR）の数値誤差を避けられる。見た目は visual 専用の円柱ジオメトリで描画する。
- 摩擦はエアクッション上の空気抵抗・残留摩擦をまとめた粘性減衰（等方性）でモデル化し、ドメインランダム化の対象にする。

## D-005 接触は明示的 `<pair>` のみ、condim=1（法線のみ）
- 理由: 不要な接触計算を避け、反発係数を接触ペアごとに solref で制御する。接線摩擦なしで反射則（法線成分 −e 倍、接線成分保存）が成り立ち、物理予測モデルと整合する。

## D-006 低レベル制御: 目標位置 → 加速度制約付き速度指令 → MuJoCo 速度サーボ
- 全制御器（Reactive / Physics / RL / Hybrid）の出力は「目標位置」に統一し、`MotionController` が軸ごとの v_max・a_max・可動範囲を守った速度指令に変換する。
- 理由: 学習アルゴリズムの差し替えが物理側の変更を要求しない。AI の行動も必ず物理制約を通る。

## D-007 座標系
- 原点はテーブル中心、x は長手方向（自ロボットのゴールは x = −L/2）、y は幅方向、z は上。
- 相手側の制御器は x を反転した「プレイヤー座標系」で動作し、同じ制御器クラスを再利用する。

## D-008 物理ステップ 1 kHz・接触ばね固有振動数 600 rad/s
- 代替案: 500 Hz + MuJoCo 既定の timeconst/dampratio。
- 理由: MuJoCo の dampratio 方式では剛性 ∝ 1/(τζ)² となり、反発係数 0.85（ζ≈0.05）では 500 Hz で数値的に破綻（実測で速度が 40 倍に跳ね上がる）。固有振動数 ω を固定し τ=1/(ωζ) とする方式で、1 kHz・ω=600 rad/s のとき目標反発係数を ±0.03 で再現（tests/physics）。最大めり込み 8 mm @5 m/s。

## D-009 低レベル制御の多重レート（判断 50 Hz / 軌道生成 250 Hz / サーボ 1 kHz）
- 理由: 実機ロボットと同様の階層構成。軌道生成を 1 kHz → 250 Hz にして環境ステップを約 3 倍高速化（プロファイルで MotionController が支配的だったため）。接触時間（約 5 ms）> 4 ms なので接触・ゴールの検出漏れはない。

## D-010 時刻付き打撃指令（switch_target / switch_delay）
- 理由: 50 Hz の判断周期では打撃開始が最大 20 ms ずれ、2 m/s のパックで 4 cm の打点誤差（方向誤差 10–30°）になった。低レベル側（250 Hz）で指定時刻に目標を切り替える方式にして、打撃方向誤差を平均 0.1–0.7° に改善。
- 併せて: 停止前提の到達時間推定、打点時刻のコミットメント（ヒステリシス）、方向を保つ協調スルーレート制限。

## D-011 相手は「人間らしく不完全」に設計
- 反応遅延（reactive 0.08 s / aggressive 0.12 s / physics 0.10 s / defensive 0.18 s）、速度係数（defensive 0.8）、誤ったモデル（減衰 0.10・反発 0.92）。
- 理由: 完全情報の物理制御同士では 0–0 ばかりで比較にならなかったため。遅延は人間の反応時間（0.1–0.2 s）相当。

## D-012 Hybrid の行動空間: MultiDiscrete[戦略4 × 狙い5 × 速度3]、10 Hz
- 戦略 = 防御 / ストレート / 左壁バンク / 右壁バンク、狙い = ゴール線上の y（±0.09 m）、速度 = 2.5/3.5/4.5 m/s。実行（予測・タイミング・打撃幾何）は物理プランナが 50 Hz で担う。
- 理由: 固定戦略の比較実験で、相手ごとに最適な戦略が異なる（例: Stationary 相手はバンク 7.3 点/分 vs 中央 1.7 点/分）ことを確認。学習で状況・相手に応じた選択を獲得させる。

## D-013 観測: 15 次元の状態ベクトル（ゲーム状態 = ポゼッション時計）
- 残り時間・スコア差は学習（1 点で終わるエピソード）と評価（60 s の試合）で分布が異なるため除外し、ルール上意味のある「パックが現在の陣地に入ってからの時間」を採用。Hybrid は物理特徴量 12 次元（防御線通過予測、最速打点、各シュートの空きレーン、バンク可否）を追加。

## D-014 報酬: 純 RL はポテンシャル型整形、Hybrid は疎報酬
- 純 RL: ゴール ±10、打撃 +0.3、枠内打撃 +0.7、防御 +1、自陣方向への打撃 −0.5、エネルギー/範囲外ペナルティ、ポテンシャル型整形（パック接近・防御線整列）。整形は γΦ(s')−Φ(s) で最適方策を変えない。
- Hybrid: ゴール ±10、枠内打撃 +0.5、防御 +0.5、自陣方向 −0.5 のみ。

## D-015 学習はローカル CPU を主、Colab は検証済みの代替経路
- 事実: SB3 の MlpPolicy PPO は環境律速で CPU が速い。ローカル（20 スレッド）で 1 本 20–40 分。Colab の標準ランタイムは vCPU が少なく、本ワークロードでは CU を消費して遅くなる見込み。
- 対応: 公式 `google-colab-cli` 0.7.4 をコンテナに導入し、`--help` で全コマンドを確認した。ジョブ計画・実行スクリプトと Drive への再開可能チェックポイントを用意した。

## D-016 計測フィルタとオンライン適応
- α-β フィルタ（物理モデル予測 + 衝突でのゲートリセット）でセンサノイズ下の予測を安定化。
- オンライン同定（自由飛行区間の ln|v| 回帰で減衰率、側壁バウンドで反発係数）を事前分布と証拠重みで混合。未知テーブルへの適応機能として評価する。

## D-017 評価プロトコル
- 学習と評価のシードを分離（評価 10000 番台）、60 s の試合、相手 5 種 × 条件 4 種（nominal / randomized / unknown_sticky / unknown_bouncy）× 20 試合、平均・標準偏差・95% CI、未知条件は学習に一切使わない。

## D-018 ノイズに強い打点コミットメント（許容幅・静止判定・距離ベース発射）
- 観測ノイズで打点が毎周期数 mm 動き、厳しい許容（slack ≥ −5 ms）だとコミットメントが外れて再計画が繰り返され、打撃が発動しなかった（ノイズ下で得点 1/3 以下）。
- 許容幅 0.06 s、0.1 m/s 未満の速度を 0 とみなす静止判定、助走位置から 3 cm 以内での発射判定を導入。打撃線は実位置から再照準するため精度は落ちない。

## D-019 学習中は作業ツリーを再チェックアウトしない
- 学習中に改行コード正規化のため `git reset --hard` を実行し、追跡対象の `progress.csv` が置き換わって以後のログが失われた（プロセスは削除済み inode に書き続けた）。
- 対応: `scripts/rebuild_progress.py` で SB3 の標準出力ログから完全に再構成（行数・最終ステップを確認）。今後は学習完了後にのみ再チェックアウトする。

## D-020 Hybrid の Stage 1–3 は物理実行器が担う
- 打撃・直線防御・反射防御の技能は物理プランナが既に持つため、Hybrid の学習は Stage 4（単純な相手）から開始し、Stage 5（相手 5 種 + DR）に進める。純粋 RL は Stage 1 から全段階を学習する。
